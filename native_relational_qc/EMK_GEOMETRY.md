# Exact EMK information and curvature queries

Author: Monty. 23 October 2026.

The calculator now evaluates the actual finite-cut tensor used in the recent
physics work, rather than treating the word “tensor” as a sufficient connection.
The adapter uses CID-D2 equation (2), the native EMK multiplication relations,
and the existing exact circuit engines. It returns the information metric,
the imaginary curvature component, and exact dependencies among the requested
real tangent directions. Both tensor halves must reconstruct exactly.

This adapter explicitly selects a normalized pure circuit state
P=|psi><psi| and controls B_a=-i H_a, where each H_a is a signed Pauli word.
The coefficient field is the already declared Q(sqrt(2),i). This admits a useful
finite sector; it does not claim to reconstruct every CID-D2 control, continuous

CID-D2's selected 4/5,2/5,1/5 cut is not a saved Clifford+T preparation here.

The complex representation and positive pairing remain explicit choices from

physical clock, metric-selection theorem, hardware or quantum-gravity result
is supplied by this adapter. CID-D2 itself distinguishes its finite action
model from those physical claims.

## Native multiplication is executed

`emk_tensor.EMKBlock` stores aI+bK+cR+dRK with exact coefficients. For the
ordered basis R^r K^k, r,k in {0,1}, composition is

\[
(R^rK^k)(R^sK^t)=(-1)^{ks+rs}R^{r\mathbin{\oplus}s}K^{k\mathbin{\oplus}t}.
\]

The first sign comes from moving K past R; the second comes from R²=-I.
Distributing this rule defines every block product. Dagger conjugates the
coefficients and negates the R channel. The existing circuit representation is

\[
K=\begin{pmatrix}1&0\\0&-1\end{pmatrix},\quad
R=\begin{pmatrix}0&-1\\1&0\end{pmatrix},\quad
X=RK,\quad Y=iR,\quad Z=K.
\]

The Pauli product table used by the new query is **generated by this EMK
multiplication**, including the central factors ±1 and ±i. It is not computed
by an external SDK. For example, XY=iZ but YX=-iZ. The source EMK-2 uses the
equivalent presentation K=X; conjugation by (I-R)/sqrt(2) maps that K to the
calculator's K while preserving R. CID-D2's displayed controls (R,J,L) map
directly to H=(Y,-X,Z), since J=iRK and L=-iK in the calculator basis.

## Exact reduction to observable calculations

Put h_a=<psi|H_a|psi>. Then

\[
X_a|\psi\rangle=-i(H_a-h_a)|\psi\rangle,
\qquad
Q_{ab}=\langle H_aH_b\rangle-h_a h_b.
\]

This follows by expanding [B_a,P] and using P²=P and normalization. Thus no
full-register density matrix is needed. Each ordered product H_aH_b is a
single Pauli word times its retained exact phase. Identical complete words
share one expectation evaluation; identity is known exactly. The selected
factored or observer engine performs the remaining evaluations.

Q is a Hermitian Gram matrix of X_a|psi>. Its real symmetric part g is the
information metric for these selected directions; its imaginary antisymmetric
part Omega is the CID-D2 tensor component. The full cut-induced curvature
operator C_ab is not returned by this query. For a rank-one cut it satisfies
C_ab=2i Omega_ab P. Ambient curvature and induced curvature remain distinct.

For |0> with H=(X,Y), g=diag(1,1) and Omega_01=1. For |1>, the metric is
identical while Omega_01=-1. Keeping only g would lose a real distinction.

## Exact dependency certificate

Exact field row reduction of g selects independent columns J and real
coordinates C such that g[:,j]=sum_r g[:,J_r] C_rj. No small eigenvalue,
tolerance, SVD truncation or probability-only equality is used.

For a real vector v, v^T g v=||sum_a v_a X_a|psi>||². Consequently a real
null direction of g is a null direction of the full complex tangent Gram
matrix as well. With the selected column basis this gives

\[
\boxed{Q=C^\dagger Q_{J,J}C.}
\]

The implementation reconstructs every entry of Q and checks exact equality
before returning the certificate. Output includes J, C and a real nullspace
basis. This is a certificate for the requested final-cut tangent tensor.
It is not a certificate that two entire circuits or histories are equal.

`real_tangent_rank` and `complex_gram_rank` are separately reported. For the
|0>, X/Y example they are 2 and 1: two independent real directions must not be
collapsed merely because their complex tangent vectors are proportional.

For a Bell pair and H=(X_0,X_1,-X_0,I), J=[0] and C=[1,1,-1,0]. The full
4×4 tensor reconstructs from one retained entry. Three distinct nonidentity
expectations are evaluated. This reduces redundant observable evaluations and
certifies directional dependence; it does not reduce MPS bonds or accelerate
every circuit. The independent [streaming upgrade](STREAMING_CONTRACTION.md)
addresses circuit contraction and has its own frozen measurements.

## Calculator request

```json
{
  "schema": "nrqc-calculator-v1",
  "n_qubits": 2,
  "operations": [["h", [0]], ["cx", [0, 1]]],
  "contraction": "streaming",
  "queries": [{
    "id": "native_geometry",
    "kind": "geometry",
    "generators": [
      {"paulis": {"0": "X"}},
      {"paulis": {"1": "X"}},
      {"sign": -1, "paulis": {"0": "X"}},
      {"paulis": {}}
    ]
  }]
}
```

Each generator is one signed Pauli word; sign defaults to +1 and must be ±1.
The query accepts 1–8 directions. Generator order defines matrix row/column
order. Exact Q entries, certified decimal enclosures for g and Omega, means,
dependencies and evaluation counts are returned. The 256-evaluation request
cap includes all distinct nonidentity expectations needed by every geometry
query. Cache sharing is within a query, not across separate queries.

Existing per-scalar backend budgets apply to each expectation. Postprocessing
has at most eight rows and uses the same coefficient-bit limit. Its field
operations are not charged to backend `max_work`; the worker wall cap covers
them. A failure discards the entire unfinished tensor. Identity-only queries
require no backend evolution. The existing circuit/request hashes retain the
declared circuit and requested generators.

```bash
python -m native_relational_qc calculate \

python -m native_relational_qc calculate \
```

This is a structured demonstration, not an arbitrary 50-qubit geometry claim.

## Why the full UGD numeral container is not substituted

The UGD-A0 counterexample separates two retained digit/ledger states even
though their total seam charge agrees. Strict carry addition is not
associative; replacing the calculator's field with that operation would
invalidate ordinary contraction reassociation. Total-charge equality is a
different, explicitly lossy target and is not used to merge histories.

There is also a specific phase-adapter mismatch in the pinned UGD-1 source.
Its phase alphabet treats a as a root-of-unity exponent. `mul_digits` stores
`(a*b) % K`, whereas multiplying the represented phases requires
`(a+b) % K`. At K=4, a=b=1, the source returns exponent 1 while i*i=-1
requires exponent 2. The existing T3 certificate checks its declared index
rule and scale projection; it does not establish that this digit product is
a homomorphism to quantum phase multiplication. This does not invalidate its
separate scale or charge-conservation checks. It blocks this particular
direct substitution. The original UGD implementation is left unchanged.

Admitting a fuller UGD carrier needs an explicit product/equality contract
and a faithful adapter for the needed phase and ledger observations. Neither
the final-cut Q nor a phase exponent modulo K recovers a full transport record.
The circuit remains retained; no claim of reconstructing its entire UGD
history from Q is made.
